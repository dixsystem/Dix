Protocolo ACP — AppIA Communication Protocol

Formato ACP: CPU:GOV=PWR|CPU:LOAD=82|MEM:SWP=60|NUMA=1|GPU:PWR=125
64% menos bytes que JSON equivalente

Analizado por multi-IA: ChatGPT (autor), DeepSeek (revisor)
Conclusión: óptimo para comunicación IA↔IA (40-60% mejora). NO para humano↔IA.

Fases de implementación ACP (prioridad):

  • ALTA: Cache local ~/.config/dix/state.json — hash SHA256 del ACP — objetivo: 2º análisis < 100ms
  • MEDIA: ACP encoder en Rust + MiniNexus para comparación por embedding
  • BAJA: Tensor Arena en VRAM para comunicación ultra-rápida MiniNexus↔NEXUS
  • FUTURO: NEXUS Global cache compartido entre usuarios

AppIA DixKontrol v2 — Daemon Adaptativo

Concepto central: En lugar de optimización manual (el usuario pulsa botón), un daemon de sistema monitoriza continuamente los procesos activos y ajusta el kernel automáticamente según el contexto — sin intervención del usuario.

Arquitectura del Daemon:

daemon (Rust systemd service)
  ├─ ProcessWatcher (inotify /proc + perf counters)
  │   └─ ContextDetector (confidence score + hysteresis timer)
  ├─ EventWatcher (logind/UPower D-Bus)
  ├─ ProfileEngine (profiles.json generados por Claude en setup)
  │   └─ TransitionManager (cambios graduales, evita jank)
  ├─ KernelWriter (sysctl + sysfs via pkexec / cap_sys_admin)
  ├─ RollbackGuard (snapshot antes de cada transición)
  └─ IPCServer (Unix socket → UI v1 / tray icon)

Perfiles de contexto detectados:

Proceso detectadoPerfil activadoAcción kernel
cargo/gcc/makeCompilaciónCPU scheduler + I/O, latencia NVMe reducida
Juego + GPU-boundGamingGovernor performance, libera RAM cache
DaVinci/Premiere/KdenliveEdición vídeovm.dirty_ratio, kyber agresivo

python+torch/cudaML Traininghugepages, kyber, governor performance

DixKontrol v2 — App de Control en Tiempo Real

Directorio: /home/alons/dix-kontrol/ (app Tauri independiente de Dix)
Distinción: Dix = análisis + optimización IA. DixKontrol = control directo en tiempo real sin IA.
Estado: Publicado en GitHub. Pendiente documentar toggle AUTO ON/OFF.

Features implementadas en DixKontrol v2:

  • 12 barras per-core (i5-12400) con % de uso + frecuencia en tiempo real
  • Temperatura CPU x86_pkg_temp en gauge segmentado (verde/amarillo/rojo, alerta throttling)
  • RAM + SWAP con zRAM integrado
  • 4 perfiles: Gaming, Compilación, Descarga, Reposo — una sola contraseña pkexec
  • Auto-detección de workload escaneando /proc cada 5 segundos
  • nice/ionice automático por perfil (Steam, cargo, gcc, torrents)
  • zRAM 2/4/8 GB configurable vía pkexec

ReglaMotivo
NUNCA tocar GPU, nvidia, nouveauHardware gráfico es crítico, optimizaciones del kernel pueden dejar sin vídeo el sistema
NUNCA kernel.numa_balancing=0Puede degradar el rendimiento en sistemas con un solo nodo NUMA
NUNCA vm.dirty_ratio > 15Valores altos pueden causar pérdida de datos en corte de corriente
NUNCA transparent_hugepages=neverPuede impactar negativamente cargas de trabajo de memoria
SIEMPRE /usr/bin/pkexec (ruta absoluta)Evita path injection — la ruta relativa puede ser interceptada
SIEMPRE /sbin/sysctl (ruta absoluta)Misma razón de seguridad que pkexec
